# Android-версия: план

Цель — APK SoSamb0 Music для телефона из того же кода (Tauri 2 умеет Android). Звуковой движок и
весь интерфейс переиспользуются; переписать нужно вывод звука, работу в фоне и раскладку под палец.

## Состояние (17.11.2026)

(`scripts/android-build.ps1`), на телефоне ещё **не проверялся** — телефон не был подключён.

Осталось: фоновое воспроизведение и MediaSession (раздел 4), перестановка треков пальцем

проверка на устройстве, релизная подпись.

## 0. Инструменты (установлены)

Без Android Studio, только командная строка — в `C:\Users\EpicMonkey\Android`:
`jdk17` (Temurin 17), `Sdk` (platform-tools, platforms;android-36, build-tools;36.1.0,
ndk;28.2.13676358, cmdline-tools). Переменные пользователя `JAVA_HOME`, `ANDROID_HOME`, `NDK_HOME`
и `platform-tools` в `Path` заданы. Цели Rust для Android стоят.

**Не ставить в `%LOCALAPPDATA%` из Claude**: приложение Claude — пакет MSIX, и Windows тихо
перенаправляет его записи в `AppData\Local` внутрь `Packages\Claude_…\LocalCache`. Вне Claude этих
файлов не видно, а Java не может создать там служебный сокет («Unable to establish loopback connection»).

Сборка:

```bash
powershell -ExecutionPolicy Bypass -File scripts/android-build.ps1            # → SoSamb0-Music-arm64.apk
powershell -ExecutionPolicy Bypass -File scripts/android-build.ps1 -Install   # и установить по USB (adb)
```

Скрипт собирает движок в release (отладочный декодер на телефоне может заикаться), а APK — debug-
вариант, подписанный локальным отладочным ключом. `tauri android build` сам кладёт библиотеку в проект
символической ссылкой — без «Режима разработчика» Windows это запрещено, скрипт тогда копирует её.

Отступы под статус-бар, вырез и жестовую панель делает `MainActivity.kt` (padding корневого вида), а не
`env(safe-area-inset-*)` — его поддержка в WebView зависит от версии.

Телефон: *Настройки → О телефоне* — 7 раз «Номер сборки» → *Для разработчиков* → «Отладка по USB».
Проверка: `adb devices`.

## 1. Каркас: приложение запускается на телефоне

```bash
npm run tauri android init      # создаст src-tauri/gen/android (закоммитить)
npm run tauri android dev       # сборка, установка на телефон, горячая перезагрузка интерфейса
```

Сначала проект **не соберётся** под Android — вот что привязано к десктопу:

| Место | Проблема | Что сделать |
| --- | --- | --- |
| `audio/engine.rs:144` → `output::spawn` | `output.rs` только для Windows (WASAPI) | временно — заглушка вывода, затем раздел 2 |
| `Cargo.toml`: `tauri` feature `tray-icon`, `tauri-plugin-global-shortcut`, `tauri-plugin-single-instance` | только десктоп | перенести в `[target.'cfg(not(any(target_os = "android", target_os = "ios")))'.dependencies]`, в коде `#[cfg(desktop)]` |
| `lib.rs`: регистрация этих плагинов, `media::init_tray`, `media::init_controls` | то же | `#[cfg(desktop)]` |
| `media.rs` (souvlaki, трей) | на Android нет | только десктоп; на Android — MediaSession (раздел 4) |
| `discord.rs` | на Android Discord-pipe нет | компилируется (ветка `not(windows)`), в интерфейсе скрыть |
| `capabilities/default.json` | разрешения окна и горячих клавиш | разделить на файлы с `"platforms": ["windows"]` и `["android"]` |
| `src/lib/window.ts`, `native.ts`, `Titlebar.svelte`, `MiniPlayer.svelte` | API окна, мини-плеер, глобальные клавиши | на мобильном не вызывать (проверка платформы, `@tauri-apps/plugin-os` или флаг из Rust) |

**Сеть.** Android по умолчанию запрещает незашифрованный `http://` — а Navidrome дома обычно по
`http://192.168…`. Нужен `android:usesCleartextTraffic="true"` (или network security config) в
`gen/android/app/src/main/AndroidManifest.xml`, плюс разрешение `INTERNET` (Tauri добавляет сам).

`ureq` с `rustls` (крипто `ring`) собирается компилятором из NDK — нужен `NDK_HOME`.

## 2. Звук: вывод через AAudio (сделано — `audio/output_android.rs`)

Как сделано (ради качества): поток **float 32** (микшер Android работает во float, 24 бит проходят без
обрезки и без дизеринга) на **родной частоте устройства** — если частота трека совпадает, пересчёта нет,
иначе работает наш FFT-ресемплер (rubato, f64), а не ресемплер Android неизвестного качества. Режим
`PowerSaving`, блокирующая запись в том же цикле, что `output.rs`. Позиция считается по реально
проигранным кадрам (`frames_written − frames_read`), а не по записанным — иначе тексты убегали бы на
длину буфера. Пауза ждёт, пока затухание доиграет из буфера устройства. Отключение устройства (наушники,
Bluetooth) → `failed` → движок открывает поток заново на новом маршруте. Атрибуты usage/content =
media/music — значения AAudio по умолчанию (явная установка в крейте `ndk` требует API 28).

Исходный план:

Движку всё равно, куда выводить: он общается с выводом через контракт в `audio/backend.rs`
(`OutCmd::Open/Start/Pause/Flush/Close/ListDevices`, общее состояние `OutShared` с `frames_played`,
громкостью, флагом дизеринга, `failed` и `tap` для визуализатора; данные — кольцевой буфер `rtrb` со
стерео f64). Нужно написать `audio/output_android.rs` с тем же поведением, что `output.rs`.

- Рекомендация: крейт `ndk` с фичей `audio` — Rust-обёртка над AAudio (Android 8+), без C++.
  Альтернатива — `oboe` (обёртка над C++ Oboe) или `cpal`.
- Поток AAudio с колбэком данных: в колбэке читать кольцо, конвертировать (`convert.rs` уже умеет i16/i24/
  i32/f32 и дизеринг), учитывать `frames_played`, при опустошении писать тишину.
- Частота: запрашивать частоту трека; если устройство не может — ресемплер движка уже есть
  (`DeviceFormat.rate` возвращается из `Open`, движок подстроится сам).
- Режимы: `PerformanceMode::LowLatency` не нужен — для музыки важнее экономия батареи
  (`PowerSaving`), буфер побольше.
- Пауза/flush с короткой затухающей громкостью — как в `output.rs`, чтобы не щёлкало.
- Bit-perfect на Android: для USB-ЦАП на Android 14+ есть `AudioMixerAttributes` с
  `MIXER_BEHAVIOR_BIT_PERFECT` (Java/Kotlin API) — отдельная задача на потом. Встроенный выход телефона
  bit-perfect не бывает — в окне «Звуковой тракт» это надо честно показывать.

## 3. Интерфейс под телефон

Сейчас раскладка десктопная (боковая панель 228 px, панель плеера снизу, наведение мышью).

- Нижняя навигация вместо боковой панели: Главная · Поиск · Библиотека (альбомы, треки, исполнители,
  жанры, избранное) · Плейлисты (обычные и умные).
- Мини-плеер над навигацией; полноэкранный плеер открывается свайпом вверх, закрывается свайпом вниз.
- Всё, что сейчас появляется только при наведении (сердечко, «⋯», галочки выбора), на сенсорном экране
  должно быть видно всегда или по долгому нажатию.
- Контекстное меню → нижний лист (bottom sheet). Выбор нескольких — долгое нажатие на трек.
- **HTML5 drag-and-drop на сенсорных экранах не работает**: перестановку в очереди и плейлисте сделать
  на pointer-событиях (долгое нажатие на ручку строки → перетаскивание).
- Окно «Звук» и «Настройки» — на весь экран. Скрыть то, чего нет на Android: эксклюзивный WASAPI, трей,
  мини-плеер, глобальные клавиши, масштаб интерфейса, Discord.
- Безопасные отступы под вырез и жесты: `env(safe-area-inset-*)`.
- Отлаживать удобно в браузере: `npm run dev`, демо-библиотека, в панели браузера
  `resize_window` с пресетом `mobile`.

## 4. Работа в фоне и управление с экрана блокировки

Без этого Android остановит музыку, когда погаснет экран.

- **Foreground service** с типом `mediaPlayback` и уведомлением; держать его, пока играет музыка.
- **MediaSession**: название, исполнитель, обложка, кнопки на экране блокировки, в шторке, на
  Bluetooth-наушниках и в Android Auto. События кнопок → те же действия, что сейчас приходят из
  `media-key` (`src/lib/native.ts` → `runAction`).
- **Аудиофокус**: пауза при звонке/другом плеере, приглушение для уведомлений.
- Пауза при отключении наушников (`ACTION_AUDIO_BECOMING_NOISY`).
- Реализация — Kotlin внутри `gen/android` или отдельный Tauri-плагин для мобильных; связь с Rust через
  команды/события Tauri.

## Порядок работы

1. Установить инструменты (раздел 0) — делает пользователь.
2. `tauri android init` + развести десктопный код по `cfg` + заглушка вывода → приложение открывается
   на телефоне, вход на сервер и навигация работают.
3. Вывод AAudio → есть звук.
4. Мобильная раскладка.
5. Фоновое воспроизведение и MediaSession.
6. Полировка и релизная сборка.

Десктопная версия после каждого шага должна по-прежнему собираться (`npm run tauri build`) и проходить
`cargo test --lib`.
